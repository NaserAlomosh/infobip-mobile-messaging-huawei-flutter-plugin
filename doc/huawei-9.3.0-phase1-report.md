### Confirmed manifest blocker

Both published AARs contain manifest package `com.infobip`:

- `com.infobip:infobip-rtc:2.5.28`
- `com.infobip:google-webrtc:1.0.45036`

AGP 9 changes `android.uniquePackageNames` from false to true. Both application
manifest tasks now reject this formerly nonfatal shared namespace. Native library
unit-test manifest merging still emits a warning, which explains why native tests
can pass while APKs fail. Flutter 3.47/built-in Kotlin would not fix artifact manifests.

Android documents `android.uniquePackageNames=false` as a temporary migration
option. It has **not** been applied: this task prohibits bypassing compatibility
errors. A narrowly scoped exception was requested; absent owner approval, the check
stays enabled. Changing/repacking vendor AAR manifests, changing package namespaces,
or upgrading RTC without owner approval was not attempted.

The initial combined online native/application run was interrupted during Flutter
ABI artifact downloads, then native tests were rerun separately and completed.
Offline application checks exposed uncached Flutter ABI artifacts in addition to
the independently reproduced namespace failure. A subsequent online run downloaded
the required binaries and passed both Debug and Release duplicate-class checks.
The manifest blocker persists independently of binary downloads.

## E. Consumer migration impact

This source candidate raises Flutter to >=3.44.4 and Dart to ^3.12.2. Applications
must install Android API 37 and compile with 37, use AGP >=9.1.1 with its compatible
Gradle (9.3.1 for this tested candidate), and retain their own namespace/application
ID. The plugin still requires minSdk 26; example targetSdk remains 36. No targetSdk
migration is included.

For the selected Flutter 3.44.4 route, keep KGP 2.2.10 and explicit Java/Kotlin 17
bytecode, add `android.builtInKotlin=false` and `android.newDsl=false` to the **host**
Gradle properties, and enable resValues where the host generates them. Plugin-local
properties do not configure consuming hosts. Add
`android.onlyEnableUnitTestForTheTestedBuildType=false` if both test variants are
required. Run native tests with JDK 21. AGP itself requires at least JDK 17; only JDK
21 was exercised here.

The RTC namespace issue still prevents accepting this recipe as a working complete
host migration. An approved temporary namespace exception or a separately approved
vendor-artifact correction is required before downstream build certification.
Flutter 3.47+ with built-in Kotlin remains a documented alternative, not a tested
claim for this candidate. No public MethodChannel, EventChannel or Dart API change
is required.
